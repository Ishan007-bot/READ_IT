## Slide 2 — Document Analysis: Critical Bottlenecks

**Title:** Why is "chat with a PDF" actually hard?

**Bullets:**
- **Hallucination** — LLMs invent plausible facts that don't exist in the source
- **No source verification** — standard chat answers can't be traced back to a passage
- **Context-window limits** — dumping a 200-page PDF into a prompt costs more and degrades accuracy
- **Topic drift** — models leak training data into supposedly document-only answers
- **No refusal mechanism** — out-of-the-box LLMs try to answer everything
- **Multilingual gaps** — most pipelines silently degrade on non-English queries
- **Citation tampering** — even with RAG, models can cite pages that don't exist

**Speaker notes:**
A naive "send the PDF to the LLM" approach breaks down in seven places.
Each of these is a known failure mode that's been documented in
production RAG deployments. The job of ReadIt is to close every one of
these gaps.

## Slide 3 — Core Objectives for the Strictly Grounded Agent

**Title:** What "good" looks like

**Bullets:**
- ✅ Answer **only** from the uploaded PDF — never from training data
- ✅ **Cite the page** for every factual claim using `[p. N]`
- ✅ Refuse out-of-scope questions **explicitly** — never guess
- ✅ Handle ambiguous, multilingual, and topic-adjacent queries gracefully
- ✅ Be **testable** — deterministic for the same query + corpus
- ✅ Be **observable** — every claim must be auditable to a source passage
- ✅ Survive both **general-knowledge** and **document-adjacent** out-of-scope traps

**Speaker notes:**
These are the seven design constraints I worked back from. The non-obvious
one is the last bullet: refusing "What is the capital of France?" is easy.
Refusing "What's the R-7's TCP port assignment?" — a question that *sounds*
like it could be in a robotics document but isn't — is the harder bar.

## Slide 4 — Our Solution: A Reliable RAG-Based Conversational Agent

**Title:** ReadIt's seven-layer guarantee

**Bullets:**
- **Tool-calling gate** — the agent must call `retrieve_from_pdf` before answering
- **Hybrid retrieval** — FAISS dense vectors + BM25 sparse keyword + RRF fusion
- **Confidence threshold** — weak retrievals trigger an explicit refusal hint
- **Citation enforcement** — answers without `[p. N]` get re-prompted; if still missing, hard-refused
- **Strict system prompt** — refusal examples baked in for general knowledge, creative, and document-adjacent
- **Per-turn re-grounding** — every chat turn re-queries the index, even with conversation history
- **Audit-friendly response** — every reply ships with retrieved context, tool-call count, and a `refused` flag

**Speaker notes:**
Each of these is a defence layer. If the model ignores the system prompt,
the tool gate catches it. If it invents a citation, the regex catches it.
If it can't find the answer in retrieval, the threshold tells it to refuse.
It's defence in depth — no single layer is enough on its own.

## Slide 5 — System Architecture: End-to-End Data Pipeline

**Title:** Architecture overview

**Diagram (paste as image or recreate):**

```
   User question
        │
        ▼
┌──────────────┐  ┌──────────────┐
│  Streamlit   │  │   FastAPI    │   ← two interfaces, one service layer
└──────┬───────┘  └──────┬───────┘
       └──────┬──────────┘
              ▼
      ┌────────────────┐
      │  PDF Service   │
      └────────┬───────┘
               │
   ┌───────────┼───────────┐
   ▼           ▼           ▼
┌────────┐ ┌────────┐ ┌──────────┐
│Ingest  │ │Retriever│ │  Agent  │
│PyMuPDF │ │FAISS    │ │Groq Llama│
│→chunks │ │+BM25+RRF│ │+ tools   │
└────┬───┘ └────┬───┘ └────┬─────┘
     │         ▲          │
     │         │          ▼
     ▼         │     ┌──────────────┐
┌──────────┐   │     │  Citation    │
│ Persist  │◀──┘     │  enforcement │
│ index    │         └──────┬───────┘
└──────────┘                ▼
                    Audited response
                    (answer + citations
                     + retrieved + flags)
```

**Bullets (alongside diagram):**
- Both UIs delegate to one **PDF Service** — single source of truth
- Ingest happens **once** per PDF (sha256-keyed; cached on disk)
- Retrieval is **rebuilt at search time** from the persisted FAISS + BM25
- Agent **must** route through the retrieval tool — system prompt forbids shortcutting
- Citation enforcement is the **last gate** before the response leaves

**Speaker notes:**
The key architectural decision is the single PDFService. The Streamlit UI
and the FastAPI endpoint are thin shells — they do nothing the service
doesn't do. That means the same code path is exercised by my pytest
harness *and* by an end user clicking buttons. There's no behaviour
divergence to debug.

## Slide 6 — Design Pillars

**Title:** Six pillars that hold up the agent

| Pillar | What it does | Where it lives |
|--------|--------------|----------------|
| 1. Strict grounding | Forces tool-call before answer | `app/prompts.py`, `app/agent.py` |
| 2. Hybrid retrieval | Dense + sparse + RRF | `app/retriever.py` |
| 3. Citation enforcement | Regex check + corrective re-prompt | `app/agent.py` |
| 4. Confidence-gated refusal | Threshold below 0.25 → tell the model | `app/agent.py` |
| 5. Multilingual | Llama 3.3 detects + responds | system prompt rule |
| 6. Audit transparency | Retrieved context + flags in response | `app/service.py`, both UIs |

**Speaker notes:**
Each pillar maps to a file or function in the repo. If you wanted to swap
out a layer — for example, plug in OpenAI embeddings instead of
sentence-transformers — you'd change exactly one method and nothing else.
This is by design. The system is intentionally easy to attack at the
boundary you care about.

## Slide 7 — System Capabilities

**Title:** What ReadIt can do

**Bullets:**
- **Upload any PDF** — drag & drop, sha256-keyed cache (no re-indexing on re-upload)
- **Chat in any language** — auto-detects, replies in the same language, citations preserved
- **Page-level citations** — every factual claim ends with `[p. N]`
- **Three classes of refusal** — general knowledge, creative requests, document-adjacent
- **Conversation memory** — multi-turn dialogue with re-grounding on every turn
- **Light + dark themes** — toggle in sidebar
- **Two interfaces** — polished Streamlit UI for humans, FastAPI/Swagger for machines
- **Reproducible** — same question + same PDF = same answer (temperature=0.1)

**Speaker notes:**
The dark mode and the gradient pill citations are not decorative — they
make grounding *legible*. A grader can see, at a glance, whether every
claim has a citation. If a sentence has no pill, that's a bug. The UI
turns correctness into a visual signal.

## Slide 8 — Demonstrating System Behavior Across Query Types

**Title:** ReadIt in action — six representative queries

| Type | Query | ReadIt's response |
|------|-------|-------------------|
| ✅ Factual | "What was the FY2025 uptime?" | "97.2% **[p. 1]**" |
| ✅ Multi-fact | "Most common failure and incident count?" | "wheel-encoder drift, 233 incidents **[p. 4]**" |
| ✅ Spec lookup | "What is the R-7 payload capacity?" | "250 kg **[p. 2]**" |
| ❌ General knowledge | "What is the capital of France?" | "Outside the scope of this document." |
| ❌ Creative | "Write a poem about robots." | "Outside the scope of this document." |
| ❌ Topic-adjacent | "What are the R-7's TCP port assignments?" | "I couldn't find that in the document." |
| 🌐 Multilingual | "¿Cuál fue el ingreso total en 2025?" | "USD 184.6 millones **[p. 5]**" |

**Speaker notes:**
Notice the difference between the last two refusal types. "Capital of
France" is *clearly* off-topic, so the agent says "outside the scope".
"TCP port assignments" *sounds* like it could be in a robotics document
— that's the harder case. The retrieval scores all came back below the
0.25 threshold, the tool result told the model "the document likely
doesn't contain this," and the model produced the right refusal.

## Slide 10 — Testing, Observability, and System Validation Protocols

**Title:** How we know it's working

**Three layers of validation:**

**1. Automated assertions** (`tests/test_agent.py`)
- Citations exist
- Cited pages match expected pages
- Required content present in valid answers
- Refusal phrasing present in invalid answers
- Tool calls ≥ 1 for factual answers

**2. Per-response audit trail**
Every `/chat` response includes:
- `answer` — the text shown to the user
- `citations` — list of `[p. N]` markers parsed
- `retrieved` — full retrieved passages with scores (for debugging)
- `tool_calls` — number of times the agent invoked retrieval
- `refused` — boolean flag for downstream consumers

**3. UI-level observability**
- Streamlit "Retrieved context" expander on every answer — shows the actual chunks the model saw
- "⚠️ Out of scope" tag on refused answers — visual signal of the agent's decision
- FastAPI Swagger at `/docs` — interactive API testing

**Speaker notes:**
Three layers: machine-checked, response-level, and UI-level. The point
isn't just to know it works — it's that *anyone else* can verify it
works without trusting me. A grader can run pytest, inspect a JSON
response, or watch the retrieved-context expander update in real time.

## Slide 11 — Future Roadmap

**Title:** Beyond a single document — towards a robust multi-document agent

**Current constraints → ten next steps, in priority order:**

1. **Cross-encoder reranking** of top-20 RRF results → improves top-1 precision
2. **Table-aware extraction** (`pdfplumber`) → preserves tabular numbers
3. **Verification pass** — second LLM scores each cited claim against its source
4. **Multi-document retrieval** with doc-aware citations (`[Doc A, p. 3]`)
5. **Per-document threshold calibration** — auto-tune refusal cutoff per upload
6. **Streaming responses** in the UI (Groq supports SSE)
7. **Conversation summarisation** — collapse old turns above N tokens
8. **OCR fallback** for scanned PDFs (Tesseract / Apple Vision)
9. **User accounts + persistent workspaces** — no re-uploads between sessions
10. **Observability dashboard** — refusal rate, avg citation count, avg tool calls

**Speaker notes:**
The current build is a single-document agent. To scale to a corpus, the
biggest unlocks are cross-document retrieval and per-document threshold
calibration — those two together would let it serve as a research
assistant against a whole library, not just one file. Items 1, 2, and 3
are about precision; 4-7 are about scale; 8-10 are about polish.
